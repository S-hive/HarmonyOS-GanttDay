# HarmonyOS GanttDay 第一期设计

- 状态：用户已审阅通过
- 日期：2026-09-12
- 工作名：HarmonyOS-GanttDay
- 参考实现：`d:\javaFail\GanttDay`（Windows / Flutter）

## 1. 产品定位

在华为 MatePad（HarmonyOS 6+）上做 **GanttDay 的原生 HAP**：个人本机甘特日程，无账号、无云、无通知。

第一期目标：日常能用日 / 周 / 月看计划、在日视图上创建和改时间、本机持久化。视觉与 Windows 版对齐（底栏三等分、右侧抽屉、网格与色条），只改平板上不成立的鼠标操作。

明确不做（第二期）：标签与过滤、色卡管理、完成「计划 vs 实际」、JSON 备份导入导出、设置页（可视时段写死）、系统通知、云同步、读写系统日历。

## 2. 平台与实现路线

- 设备：平板为主（MatePad）。不做手机适配。
- 实现：ArkTS + DevEco，打 HAP。不与 Windows Flutter 工程共代码。
- 日视图用 Canvas 画网格和色条；周 / 月用布局模块的几何结果绘制。
- 领域逻辑（时间、几何、分行、手势数学、周列布局、月跨日条）按 Windows 同名模块移植为纯 ArkTS，不依赖 ArkUI / RDB。

## 3. 第一期用户界面

### 3.1 外壳（三视图共用）

- 顶栏：`GanttDay`、后退、日期标题、前进、`今天`。
  - 日：按天翻；标题 `YYYY-MM-DD`。
  - 周：按 7 天翻；标题「M月 · 第N周」（周起周一）。
  - 月：按月翻；标题 `YYYY-MM`。
- 底栏：日 / 周 / 月三等分图标，切到对应真页面（不是占位空页）。
- 顶栏没有标签筛选、没有设置齿轮。

### 3.2 日视图

横向小时网格。默认可见 **8:00–22:00**，左右滑动查看其他小时。色条只用默认主色（霁蓝 `#457BD9`）。

- 重叠任务向下分行。
- 头尾相接（12:00 结束与 12:00 开始）不算重叠，可共一行。
- 跨午夜：库中一条任务，绘制切成两段；拖任一段等于改整条。

| 操作 | 行为 |
| --- | --- |
| 拖色条中部 | 平移计划时间 |
| 拖色条两端 | 缩放起止 |
| 空白处短拖 | 只平移时间轴 |
| 空白处点一下再按住拖，见 `2026-09-13-day-create-drag-design.md` | 进入创建（见 3.5） |
| 已有色条单击一下 | 右侧抽屉打开表单（见 3.6 与双击的区分） |
| 已有色条连续点按两下 | 删除该任务（见 3.6） |

时间吸附 **15 分钟**（四舍五入到最近 15 分钟：8:07→8:00，8:08→8:15）。最短时长 **15 分钟**。

不做：长按拖拽创建、右键完成轴、悬停提示。

### 3.3 周视图

经典周历：横轴周一→周日，纵轴当日 0:00→24:00。

- 跨日任务按自然日切开，每天一块。
- 同一天时间半开区间相交的任务左右并排分栏，不上下叠盖。
- 默认竖向滚到 8:00；今天列日期高亮。
- 点任务块一下 → 右侧抽屉编辑该任务。
- 连续点按任务块两下 → 与日视图相同，确认后删除（见 3.6）。
- 点某日表头 → 切到该日的日视图。
- 第一期不在周视图拖改时间，不在空白处创建。

### 3.4 月视图

按周行组织（周一～周日）。彩色横条跨任务覆盖的日期，条上只显示标题。

- 跨周任务每周各画一段。
- 单日条左右位置按当日已过分钟 / 1440 近似 inset；极短任务最小可见宽度 4px。
- 每个自然日最多展示 10 条；超出显示 `+N`。
- 点本月空白格、`+N` 或色条 → 进入对应日视图。非本月格子不可点。
- 第一期不在月视图拖改期。

### 3.5 创建与表单

创建路径已由 `2026-09-13-day-create-drag-design.md` 替代；不再双击立刻 60 分钟。

**双击空白创建（日视图）**

1. 仅空白网格响应；点在已有色条上走 3.6（打开表单或删除），不进入创建。
2. 两次点按落点距离 ≤ 32vp，间隔符合系统双击窗口。
3. 将第二次点击的 x 转为时间并吸附 15 分钟，得到 `start`；`end = start + 60` 分钟。允许跨午夜。
4. 在点击处附近画出默认主色预览条，并弹出锚在条旁的「新任务」标题框（约 300px 宽，不是屏幕正中对话框）。
5. 确认且标题去空后非空 → 插入任务。取消或点框外 → 不建任务。

之后可用拖条 / 抽屉改时长。不再使用「长按约 350ms 再拖」创建。

**右侧抽屉表单**

- 宽度：屏宽 40%，夹在 360–480px。左上圆角，遮罩模糊。
- 字段：标题、计划开始、计划结束。无备注、标签、色卡、实际时间。
- 计划时间行内编辑，同样 15 分钟吸附、最短 15 分钟。
- 抽屉里仍保留删除，确认逻辑与 3.6 相同。

### 3.6 删除已有时间条

主路径：**在已有色条（日视图）或任务块（周视图）上连续点按两下**。月视图色条仍只用于进入日视图，双击不删除。

1. 两次点按落在**同一条任务**上（跨午夜的两段算同一条），落点距离 ≤ 32vp，间隔符合系统双击窗口。
2. **先弹确认框**，文案带任务标题，例如：「删除「拍摄」？此操作无法撤销。」按钮：取消 / 删除。
3. 确认 → `TaskRepository.delete(id)`，关掉可能已打开的抽屉，三视图刷新。
4. 取消或点框外 → 任务不动，也不打开表单。

**与单击打开表单区分：** 手指落在色条上时，第一下先等双击窗口。窗口内第二次点到同一任务 → 走删除确认，不打开表单。窗口结束仍只有一下 → 再打开表单。因此从表单出现会比按下晚一个双击间隔，这是预期。

拖动色条（移动 / 缩放）一旦成立，取消这次的单击 / 双击识别。

**保存规则**

- 关抽屉（点遮罩、系统返回、滑关）：标题去首尾空格后若非空则写入标题与当前计划时间。
- 标题空 → 不改标题，只保存抽屉里的计划时间（第一期抽屉只从已有任务打开，不会出现「空标题新建」）。
- 新建只走双击标题框：标题去空后为空则不插入。

## 4. 模块与缝

调用方只依赖小接口；算法与存储细节关在模块内。

### 4.1 领域（无 ArkUI、无 RDB）

| 模块 | 接口 | 实现里藏什么 |
| --- | --- | --- |
| `WallClock` | 本地钟面 ↔ 墙钟分钟 | 用 UTC 算术编解码钟面，不读系统时区偏移 |
| `GanttGeometry` | 时间 ↔ 像素、吸附、最短时长 | 日视图横向轴 |
| `DaySegmenter` | 任务列表 → 当日可见段 | 跨午夜切段；恰在 00:00 结束的不在次日留空段 |
| `LaneLayout` | 段 → 行号 | 半开区间重叠检测 |
| `DayGestureMath` | 指针位移 → 新的计划起止 | 移动 / 缩放 |
| `WeekColumnLayout` | 一周任务 → 列内几何 | 按日分段、重叠簇 `columnIndex / columnCount` |
| `MonthSpanLayout` | 一月任务 → 周行条 + 每日 `+N` | 跨周切断、lane、每日上限 10 |

行为与 Windows 版同名模块对齐，便于用同一组例子单测。

### 4.2 存储缝

`TaskRepository` 是界面与持久化之间的唯一接口。第一期方法：

- `watchTasksOverlapping(rangeStart, rangeEnd)`
- `getById(id)`
- `upsert(task)`
- `delete(id)`

第一期适配器：鸿蒙 RDB。测试另做一个内存适配器，界面不改。

不做 JSON 文件网关。`complete` / 标签 / 色卡 API 第一期不出现在接口上。

### 4.3 界面模块

- `AppShell`：日期状态、底栏、打开抽屉。
- `DayGantt`：Canvas + 手势（平移 / 缩放 / 双击创建 / 双击删除）。
- `WeekPage` / `MonthPage`：消费布局模块结果。
- `TaskForm`：右侧抽屉。
- `CreateTaskPopup`：锚点标题框。

数据流：RDB 变更 → Repository 推送 → 当前视图重算布局 → 重绘。手势与表单只通过 Repository 写，不直接碰库。

## 5. 数据与存储

时间存 **本地墙钟分钟**（自 1970-01-01 00:00 起的分钟整数，按钟面解释，不做时区换算）。

### 5.1 表结构

与 Windows `schemaVersion = 2` 对齐，便于第二期互导。

**task**

| 字段 | 第一期用法 |
| --- | --- |
| `id` TEXT PK | UUID |
| `title` TEXT | 非空 |
| `planned_start` / `planned_end` INTEGER | 墙钟分钟；`end >= start + 15` |
| `created_at` INTEGER | 创建时墙钟分钟 |
| `actual_start` / `actual_end` | 始终空 |
| `is_done` | 始终 0 |
| `primary_tag_id` | 空 |
| `auto_swatch_id` | 写入厂默认 id `azure` |
| `override_swatch_id` / `notes` | 空 |

**color_swatch / tag / task_tag / setting**

建表。新库种入与 Windows 相同的出厂色卡全集；界面只用默认 `azure`（霁蓝，ARGB `0xFF457BD9`）。标签表空。设置表写入 `visibleStartHour=8`、`visibleEndHour=22`、`urgencyWindowDays=7`。第一期无设置页；日 / 周滚动读这两项可视小时（改库外的值不会在 UI 里改）。

索引：`planned_start`、`planned_end`。

### 5.2 范围查询

窗口与任务相交，不能只看开始时间：

```
planned_start < rangeEnd AND planned_end > rangeStart
```

日窗口为 `[dayStart, dayStart+1440)`，周 / 月同理用半开区间。

### 5.3 库文件

路径：应用沙箱，文件名 `gantday.db`。

打不开：提示损坏，将原文件重命名为 `gantday.db.corrupt-<时间戳>`，再创建空库并种出厂色卡。不静默覆盖、不自动删除用户数据。

单次写入失败：轻提示，进程不退出。

## 6. 手势与系统导航（平板）

- 空白短拖只平移日视图时间轴，不交给系统侧滑返回。
- 色条拖动进行中不触发底栏切页、不触发顶栏翻日。
- 创建：空白处双击。空白单击无效果，第一下不必抢单击业务。
- 删除：已有色条 / 周视图任务块上双击，先确认再删。不在空白处双击删除。
- 色条上的单击打开表单，但必须等双击窗口结束（见 3.6），避免「点两下」先打开表单再删。
- 不在色条上识别双击创建。

## 7. 错误与空状态

- 空日 / 周 / 月：只画网格，无插画、无引导页。
- 删除必须先确认（双击色条或抽屉内删除，同一套确认框）。确认前不写库。
- 非法时长在进入 Repository 之前夹到最短 15 分钟。
- 库损坏见 5.3。

## 8. 测试

领域模块用纯逻辑单测，例子与 Windows 版对齐：

- `WallClock`：钟面进出，不随系统时区漂。
- `GanttGeometry`：吸附、最短 15 分钟、时间 ↔ 像素。
- `DaySegmenter` + `LaneLayout`：跨午夜、重叠分行、头尾相接共行。
- `DayGestureMath`：移动 / 缩放后的起止。
- `WeekColumnLayout`：跨日切开、重叠左右分栏。
- `MonthSpanLayout`：跨周切断、日内 inset、每日 10 条与 `+N`。

`TaskRepository` 内存适配器：相交查询（含跨夜）、创建 / 更新 / 删除、空标题不插入。

RDB 适配器少量集成：打开库；损坏文件改名后重建。

第一期不做端到端自动点按。手工验收：日视图拖移 / 缩放 / 平移 / 双击空白创建 / 单击色条开表单 / 双击色条确认删除与取消删除；周点块、双击删除与表头；月点条与 `+N`（月双击不删）；抽屉保存与删除确认。
